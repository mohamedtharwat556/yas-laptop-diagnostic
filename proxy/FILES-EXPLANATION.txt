═════════════════════════════════════════════════════════════════════════════
🔐 ملفات إعداد Certificates (اختر واحد)
═════════════════════════════════════════════════════════════════════════════

setup-all.cmd ⭐⭐⭐ (الموصى به)
  ├─ Setup كامل تلقائي
  ├─ يحاول جميع الطرق
  ├─ يثبت dependencies
  ├─ يفعل كل شيء
  └─ الأسهل للمبتدئين

setup-cert-openssl.cmd
  ├─ استخدام OpenSSL
  ├─ يتطلب OpenSSL في PATH
  ├─ الطريقة الأسرع
  └─ يجب أن يكون OpenSSL مثبتاً

setup-cert-mkcert.cmd
  ├─ استخدام mkcert
  ├─ الطريقة الأحدث
  ├─ يتطلب mkcert مثبتاً
  └─ ينشئ certified موثوق

setup-cert.ps1
  ├─ استخدام Windows Certificate Store
  ├─ متقدم - للمستخدمين المحترفين
  ├─ قد يتطلب Administrator
  └─ يستخرج المفتاح الخاص

setup-cert-simple.ps1
  ├─ نسخة مبسطة من setup-cert.ps1
  ├─ بدون متطلبات معقدة
  └─ توفير معالجة أخطاء

🚀 ملفات التشغيل
═════════════════════════════════════════════════════════════════════════════

start-proxy.cmd
  ├─ تشغيل الـ Proxy (Batch script)
  ├─ يتحقق من Node.js
  ├─ يتحقق من Dependencies
  ├─ يتحقق من Certificates
  ├─ يشغّل الخادم تلقائياً
  └─ الطريقة الأسهل

start-proxy.ps1
  ├─ نفس الوظيفة بـ PowerShell
  ├─ يمكن استخدامه في PowerShell
  └─ نفس الحل بلغة مختلفة

npm start
  ├─ أمر بديل (من داخل المجلد)
  ├─ يشغّل: node server.js
  └─ يتطلب التحضير اليدوي

🎯 مسارات التشغيل المختلفة
═════════════════════════════════════════════════════════════════════════════

الطريقة 1: الأتمتة الكاملة (الموصى به)
─────────────────────────────────────
  setup-all.cmd
  └─ يفعل كل شيء تلقائياً
  └─ جرّب جميع الخيارات
  └─ للمبتدئين

الطريقة 2: البدء اليدوي خطوة بخطوة
──────────────────────────────
  npm install        (بالفعل مثبت)
  setup-cert-openssl.cmd  (أو setup-cert-mkcert.cmd)
  npm start

الطريقة 3: PowerShell (متقدم)
─────────────────────────────
  npm run setup:cert:ps1
  npm start

الطريقة 4: باستخدام npm commands
────────────────────────────────
  npm install       (بالفعل مثبت)
  npm run setup
  npm start

الطريقة 5: من PowerShell مباشرة
─────────────────────────────────
  powershell -ExecutionPolicy Bypass -File start-proxy.ps1

═════════════════════════════════════════════════════════════════════════════
✅ التحقق من النجاح
═════════════════════════════════════════════════════════════════════════════

بعد التشغيل، تحقق من:

1. من سطر الأوامر:
   npm test
   └─ يجب أن ترى ✅ في جميع الاختبارات

2. من المتصفح:
   https://127.0.0.1:443/proxy-health
   └─ يجب أن ترى JSON response

3. من cURL:
   curl -k https://127.0.0.1:443/proxy-health
   └─ يجب أن تعمل بدون أخطاء

4. من Vercel:
   fetch('https://127.0.0.1:443/api/hardware')
   └─ يجب أن تتصل بنجاح

═════════════════════════════════════════════════════════════════════════════
💡 ملاحظات مهمة
═════════════════════════════════════════════════════════════════════════════

1. Port 443 يتطلب تصاريح عالية (Administrator)
2. Certificate self-signed (طبيعي للـ development)
3. استخدم -k مع curl لتجاوز تحذير Certificate
4. اختبر Agent أولاً قبل الـ Proxy
5. الـ Proxy يفقط للـ localhost (127.0.0.1)
